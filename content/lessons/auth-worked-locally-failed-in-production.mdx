## Context

The CollegeInfo-Agent had a login flow using Supabase Auth. Everything worked perfectly in development — users could sign up, log in, and access role-based features. I was confident enough to deploy.

## What Broke

After deploying to the staging environment, the login flow broke silently. Users could reach the login page, but authentication would fail with a cryptic 401 error. No useful error message on the frontend.

## Symptoms

- Login form submitted successfully (no frontend errors)
- Backend returned 401 Unauthorized
- Supabase dashboard showed no failed auth attempts
- The same credentials worked perfectly in local development

## Root Cause

The environment variables for Supabase were not configured correctly in the deployment environment. Specifically:
- `SUPABASE_URL` was pointing to the correct project, but `SUPABASE_KEY` was still using the local development key (anon key from a different Supabase project)
- The frontend was sending requests to the correct URL, but the backend was validating tokens against a different Supabase instance

The mismatch meant that tokens generated by the frontend's Supabase client were invalid from the backend's perspective.

## Fix

1. Audited all environment variables across frontend and backend deployments
2. Created a single `.env.production` template with clear variable names
3. Added a startup health check that validates Supabase connectivity before accepting requests
4. Added explicit error messages for auth failures that include which Supabase project the backend is connected to (in development mode only)

## Prevention

- Never assume local environment variables are correct for production
- Add startup validation for critical service connections
- Use a single source of truth for environment configuration
- Test authentication flow in a staging environment before calling it "done"

## Lesson

A feature is not done when it works locally. It's done when it survives the environment it's supposed to live in. The gap between "works on my machine" and "works in production" is where most real bugs hide.
