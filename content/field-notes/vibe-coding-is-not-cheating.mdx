There's a growing anxiety among CS students about using AI to write code. The fear is that if you let Copilot or Claude write your functions, you're not really learning. You're outsourcing the hard part.

I get the concern. I've felt it. But after using AI tools daily for months, I think the framing is wrong.

**The tool doesn't determine the learning. Your relationship with the output does.**

If I generate a function with AI and ship it without reading it, I haven't learned anything. But if I generate it, read every line, understand why it works, refactor the parts I'd do differently, and document what I didn't know — I've learned faster than I would have without the tool.

My workflow now:
1. Write the rough version myself, even if it's broken
2. Use AI to debug, suggest alternatives, or speed up boilerplate
3. Read every line of AI-generated code before committing
4. Clean up and refactor until the code feels like mine
5. Document what I learned in the process

The danger isn't using AI. The danger is using AI without curiosity. If you stop asking "why does this work?" the moment you get a working answer, that's when you stop learning.

Vibe coding is not cheating. Vibe coding *without comprehension* is.
